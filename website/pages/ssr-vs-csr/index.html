SSR vs CSR

Same component, same async fetch. The difference: whether the server pass already painted the first yield into the HTML.

The click counter is the reactivity probe — closure state, every click runs through host.update(). The SSR card's data comes with the HTML, so hydration reuses it instead of fetching again: the card is interactive as soon as its script runs.

CSR (no server pass)

Empty in the HTML. The browser parses, the generator runs, the fetch resolves, then the first yield writes the card — empty dashed box for the duration of the fetch.

SSR (first-yield prerendered)

A vite plugin (see vite.config.ts) ran the lib in server mode, at build time and on every dev request. The <template shadowrootmode> is already in the response — instant paint, no flash — and so is the fetched data, as a <script data-ssr>. Hydration reuses it and wires bindings without overwriting the server text.
