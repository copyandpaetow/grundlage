SSR vs CSR

Same component, same async fetch. The difference: whether the server pass already painted the first yield into the HTML.

The click counter is the reactivity probe — closure state, every click runs through host.update(). Interactivity still waits for the client generator to reach the same first yield (its own copy of the fetch). SSR saves the paint, not time-to-interactive.

CSR (no server pass)

Empty in the HTML. The browser parses, the generator runs, the await fires, then the first yield writes the card — empty dashed box for the duration of the fetch.

SSR (first-yield prerendered)

A vite plugin (see vite.config.ts) ran the lib in server mode at build time. The <template shadowrootmode> is already in the response — instant paint, no flash. Hydration wires bindings without overwriting the server text.
